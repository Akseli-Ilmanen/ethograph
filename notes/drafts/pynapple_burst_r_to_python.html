MaxInterval, phase 1: find runs

Both versions walk the spike train once with the same two-state machine. R keeps an in.burst flag and writes rows into a preallocated matrix; Python keeps start (None means not in a burst) and appends (first, last) index pairs. Indices go from 1-based to 0-based.

  • The comparisons are the same: a burst starts on an interval strictly below the start threshold and ends on one strictly above the in-burst threshold.

MaxInterval, phase 2: merge close bursts

R marks every burst whose stored gap is below min.ibi, walks those in reverse to copy each end onto the burst before it, then deletes the marked rows. Python builds the merged list front to back: a run that begins too soon after the previous run's last spike extends that run.

Pythonnotes/drafts/pynapple_burst_detection.pylines 210–223
210def _log_isi_histogram(isi_ms):
211 """
212 Histogram of the interspike intervals (in milliseconds) on a logarithmic
213 axis: 10 bin edges per decade from 1 ms to the decade above the longest
214 interval, intervals under 1 ms left out, counts normalised to sum to one.
215 Returns (left edges in ms, normalised counts).
216 """
217 decades = max(1, int(np.ceil(np.log10(isi_ms.max()))))
218 edges = np.logspace(0, decades, 10 * decades)
219 isi_ms = isi_ms[isi_ms >= 1]
220 # Bin k holds edges[k] < isi <= edges[k + 1]; 1 ms itself goes to bin 0.
221 bins = np.clip(np.searchsorted(edges, isi_ms, side="left") - 1, 0, None)
222 counts = np.bincount(bins, minlength=len(edges) - 1)
223 return edges[:-1], counts / counts.sum()
  • R's hist closes bins on the right, (a, b]; NumPy's histogram closes them on the left. Python therefore bins with searchsorted to get the same edges, so an interval sitting exactly on an edge lands in the same bin.
  • The smoothing line has no Python counterpart. With ten bins per decade the histogram has at most 60 bins for any train whose longest interval is under 1000 s. At f = 0.05 R's lowess then uses a two-point neighbourhood and returns its input unchanged. Checked in R for 20 to 60 bins: zero difference.
  • The conversion to milliseconds (diff(st) * 1000, R line 114) sits one function up in Python, in _log_isi_valley.

logISI: finding the peaks

This is where the two differ most line by line. R's get.peaks is a general peak finder with a minimum peak distance Pd, a height margin Th, a peak limit Np and a skip-ahead after each peak. It is only ever called with the defaults. With Pd = 2 and Th = 0 it reduces to one rule, which Python states directly.

logISI: from peaks to threshold

Take the largest peak below the cutoff as the intra-burst peak. For each later peak, find the lowest bin between the two and score the separation with the void parameter. The threshold is the interval at the first minimum that scores 0.7 or more.

239def _log_isi_valley(isi_s, max_cutoff):
240 """
241 The threshold of Pasquale et al. (2010): the ISI at the first valley that
242 separates the intra-burst peak of the log-ISI histogram from a later peak
243 with a void parameter of at least 0.7.
244
245 Returns (has_intraburst_peak, threshold in seconds or None).
246 """
247 isi_ms = isi_s * 1000
248 if len(isi_ms) == 0 or not np.any(isi_ms >= 1):
249 return False, None
250 edges, density = _log_isi_histogram(isi_ms)
251 peaks = _find_peaks(density)
252 intraburst = [k for k in peaks if edges[k] < max_cutoff * 1000]
253 if not intraburst:
254 return False, None
255 peak = max(intraburst, key=lambda k: density[k])
256 for later in peaks:
257 if later <= peak:
258 continue
259 between = density[peak : later + 1]
260 valley = peak + int(np.argmin(between))
261 void = 1 - between.min() / np.sqrt(density[peak] * density[later])
262 if void >= 0.7:
263 return True, float(edges[valley] / 1000)
264 return True, None
  • R signals its three outcomes with three kinds of value: -1000 (no intra-burst peak), NULL (no clear valley) and a number. Python returns a pair, (has_intraburst_peak, threshold or None).
  • R computes the void parameter for every later peak and then takes the first that passes; Python stops at the first that passes. Same result.
  • The reference uses >= 0.7 where the chapter writes >; Python follows the reference so the two agree.

When the threshold lies above the cutoff, each core is widened to the spikes within the threshold of its ends. R detects a second set of bursts at the wider threshold (brs), searches it for the one overlapping each core with a nested loop and two early exits, then removes duplicates by comparing neighbours. Python looks up the run that contains the core and skips it if already taken.

The one place they disagree

logisi.find.burst is a copy of the MaxInterval loop with two changes. One is a tolerance of 10-10 on the comparisons. The other is the loop bound: n < nspikes where MaxInterval has n <= nspikes. The last interval is never examined, and a burst still open at that point is closed on the last spike whatever that interval was. Python uses the one _find_runs for both methods and examines every interval.

33def _find_runs(times, max_isi_start, max_isi_burst):
34 """
35 Phase 1: runs of spikes. A run starts at the first of two spikes closer than
36 `max_isi_start` and ends at the last spike before an interval longer than
37 `max_isi_burst`. Returns (first, last) spike indices, both inclusive.
38 """
39 runs = []
40 start = None
41 for i in range(1, len(times)):
42 isi = times[i] - times[i - 1]
43 if start is None:
44 if isi < max_isi_start:
45 start = i - 1
46 elif isi > max_isi_burst:
47 runs.append((start, i - 1))
48 start = None
49 if start is not None:
50 runs.append((start, len(times) - 1))
51 return runs
